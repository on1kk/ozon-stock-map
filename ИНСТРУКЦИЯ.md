# Карта остатков FBO Ozon — запуск за 10 минут

Что внутри:

- `fetch_data.py` — раз в час забирает из API Ozon остатки по складам и продажи за 30 дней, подтягивает себестоимость из вашей Google-таблицы, считает сток в рублях и оборачиваемость, сохраняет `data/stocks.json`.
- `warehouses.py` — справочник координат складов Ozon. Если появится новый склад, карта покажет предупреждение — добавьте одну строку в этот файл.
- `index.html` — сама карта (Яндекс.Карты, ваш ключ уже вписан).
- `.github/workflows/update.yml` — расписание автообновления (каждый час) + кнопка ручного запуска.

Себестоимость правится как обычно — в вашей Google-таблице на листе «Себестоимость товаров». Карта подхватывает изменения при следующем обновлении, ничего дополнительно делать не нужно.

---

## Шаг 1. Создать репозиторий и загрузить файлы

**Вариант А — через Claude Code (быстрее всего).** Распакуйте архив, откройте терминал в папке `ozon-stock-map` и дайте Claude Code задание:

```
Создай на GitHub приватный репозиторий ozon-stock-map у пользователя on1kk,
запушь туда всё содержимое текущей папки (включая .github),
и включи GitHub Pages: ветка main, папка / (root).
```

**Вариант Б — руками через сайт.**
1. github.com → «+» → New repository → имя `ozon-stock-map` → Private → Create.
2. «uploading an existing file» → перетащите все файлы из архива. Папку `.github/workflows/update.yml` через веб-загрузку добавить нельзя, поэтому: Add file → Create new file → в поле имени введите `.github/workflows/update.yml` → вставьте содержимое файла → Commit.
3. Settings → Pages → Source: «Deploy from a branch» → Branch: `main`, папка `/ (root)` → Save.

> Примечание: чтобы GitHub Pages работал в **приватном** репозитории, нужен план GitHub Pro (~4$/мес). Бесплатная альтернатива — сделать репозиторий публичным: в коде нет никаких секретов (ключи Ozon лежат в Secrets и в код не попадают), но файл `data/stocks.json` с остатками будет технически доступен по прямой ссылке. Решите, что вам комфортнее.

## Шаг 2. Вставить ключи Ozon (единственный секретный шаг)

1. Личный кабинет Ozon Seller → Настройки → API-ключи → создать ключ, роль **Admin read only**. Скопируйте **Client-Id** и **Api-Key**.
2. В репозитории: Settings → Secrets and variables → **Actions** → New repository secret:
   - Name: `OZON_CLIENT_ID`, Secret: ваш Client-Id → Add secret
   - Name: `OZON_API_KEY`, Secret: ваш Api-Key → Add secret

Ключи хранятся в зашифрованном хранилище GitHub, в коде и на странице их не видно.

## Шаг 3. Первый запуск

Вкладка **Actions** → слева «Обновление остатков» → кнопка **Run workflow** → Run.
Через ~1 минуту зелёная галочка = данные собраны. Дальше запуск автоматический, каждый час.

## Шаг 4. Открыть карту

Ссылка: **https://on1kk.github.io/ozon-stock-map/**
(появляется через 1–2 минуты после включения Pages; ссылку можно открыть с телефона и отправить кому угодно из команды).

## Если что-то пошло не так

- **«Данных пока нет»** на карте → не выполнен Шаг 3, либо workflow упал: откройте Actions → последний запуск → лог покажет причину (обычно опечатка в секретах).
- **Плашка «Нераспознанные склады»** внизу карты → Ozon открыл новый склад. Пришлите мне название — дам строчку для `warehouses.py` (или добавьте сами по образцу: `"НАЗВАНИЕ": (широта, долгота, "Кластер"),`).
- **Плашка «Без себестоимости»** → в Google-таблице нет этих артикулов. Такие позиции видны в штуках, но не входят в денежный итог — ровно как в вашей текущей таблице.
- **Хочется чаще, чем раз в час** → в `update.yml` замените `cron: "0 * * * *"` на `"*/30 * * * *"` (раз в 30 минут). Чаще смысла нет: Ozon сам обновляет данные с задержкой.
